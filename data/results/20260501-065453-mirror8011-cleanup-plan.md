## Stage 1: Safest next deletions

These classes are strongly mechanical, have zero preserve-tag overlap in the mirror, and are easy to express with deterministic filters.

1. `SWEEP-LOCOMO-BENCHMARK`: 953 candidates. Match `metadata.source == locomo_benchmark` or tag `locomo-test`. Samples are synthetic Caroline/Melanie benchmark conversation records. Do not delete benchmark implementation/results memories tagged `automem`, `benchmark`, or `locomo` unless they also carry `locomo-test` or source `locomo_benchmark`.
2. `SWEEP-BUILD-RESULTS`: 503 candidates. Seed `build`; require content prefix `Build succeeded in` or `Build failed in`; expected range 450-600.
3. `SWEEP-TEST-RESULTS`: 540 candidates. Seed `test`; require content prefix `Test suite passed` or `Test suite failed`; expected range 500-650. Keep deployment memories untouched.
4. `SWEEP-ENGAGEMENT-STATUS-PINGS`: 477 candidates. Match `moltbook engagement: action=` and `twitter engagement: action=` status pings; expected range 430-520.
5. `SWEEP-STARTED-SESSION`: 132 candidates. Match content prefix `Started session in project`; expected range 100-170.
6. `SWEEP-ENGAGEMENT-WORKFLOW-SUMMARY`: 527 candidates. Match `metadata.type == workflow-summary`, required tags `workflow`, `summary`, `scheduled`, and workflow name in `Moltbook Engagement`, `Twitter Engagement`, `AutoJack Daily Reflection`, or `AutoJack Blog - Multi-Source Daily Post`; expected range 500-560.

Run each as: dry-run, sample review, backup verification, execute only that filter, preserve counts, and recall probes. Stop on any count/ranking regression.

## Stage 2: Valuable cleanup, but needs stronger guards

These are likely noise, but current `runners/sweep_corpus.py` cannot express them safely enough without small runner/scenario additions.

1. Session milestones: 1,054 no-preserve-overlap candidates after excluding preserve tags. Existing filters catch bugfix/docs/feature summaries, so add `tags_forbidden_any` before executing. Forbid at least `bugfix`, `solution`, `deployment`, `preference`, `decision`, `feature`, `docs`, `security`, and `auth` for a first pass.
2. Work-pattern automation: 506 candidates. Match `metadata.type == work_pattern` or tags `work_style` + `automated` with prefix `Work pattern in `. These are generic learned summaries; safe-looking, but run after Stage 1 because they are typed as `Pattern`/`Insight`.
3. Agent result summaries: 442 candidates. Match `metadata.type == agent_result_summary` and/or tags `agent`, `result-summary`. AGENTS policy says task-result dumps should not be stored, but samples can contain useful task descriptions, so execute only after a probe set for customer/support/project queries confirms no loss.
4. Agent failures: 29 candidates. Same policy as result summaries, but smaller. Review samples; consider folding into the agent-result-summary scenario once protected by preserve probes.

Required runner/schema additions for Stage 2:

- `tags_forbidden_any`: reject candidates carrying any protected tag.
- `metadata_required_any`: allow matching `metadata.type`, `metadata.source`, and `metadata.workflow_name` without brittle content-only prefixes.
- `content_regex_any` or richer prefix lists for known generated templates.
- Optional `sample_count` and `sample_strategy` so dry-runs show first, middle, last, and random candidates rather than only newest/oldest ordering.

## Do not sweep yet

Do not sweep non-benchmark `conversation-extraction` broadly. It has 1,290 memories and 73 preserve-tag overlaps, and the samples include voice/user facts that can be valuable. Treat it as a separate quality project: cluster by source/conversation, identify synthetic or transcript-like records, and build a preservation probe set before any delete.

## Validation plan for every stage

Before and after each filter, run the same high-value probes used in the previous cleanup run: preferences, deployments, bugfixes/solutions, AutoJack published artifacts, AutoMem backup/auth/testing, automem-evals cleanup, and BEAM context. Add targeted probes for the class being deleted:

- LoCoMo: preserve actual AutoMem LoCoMo benchmark implementation/results/debug memories while removing `locomo-test` fixtures.
- Build/test: preserve deployment and bugfix memories that mention test/build commands.
- Workflow/engagement: preserve published AutoJack posts, daily context, and support-dashboard memories.
- Agent summaries: preserve customer support snippets, WP Fusion snippet/code, Slack action decisions, and GitHub issue decisions.
- Session milestones: preserve bugfix, feature, docs, deployment, and decision memories.

Acceptance: no preserve count drops, no high-value probe count drops, no top result changes for high-value probes, backup JSONL line count equals delete count, and post-delete candidate count is zero for the executed filter.

## Recommended implementation order

3. Dry-run each Stage 1 filter separately against `http://localhost:8011`; write artifacts under `data/sweep_runs/<ts>-mirror8011-stage1/`.
4. Execute one Stage 1 filter at a time only if dry-run samples are clean and recall probes are stable.
5. After Stage 1, restore a fresh mirror snapshot before evaluating Stage 2, so cumulative deletes do not hide regressions.
